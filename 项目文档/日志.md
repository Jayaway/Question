## 2. 关键决策与理由

### 2.1 数据库名 = `survey_system`（不是 `oq`）

**决策**：跟业务名解耦，使用 `survey_system`。
**理由**：commit `730f07b` 把项目从 QQ 改名成 OQ，但 OQ 只是显示名（`spring.application.name`）。数据库是数据资产，名字应该跟业务逻辑挂钩，不跟项目显示名挂钩。

### 2.2 三个 SQL 文件的分工

| 文件 | 位置 | 用途 |
|------|------|------|
| `schema.sql` | `src/main/resources/` | Spring Boot 启动自动建表 |
| `data.sql` | `src/main/resources/` | 启动自动插测试数据 |
| `sql/init.sql` | 项目根 `sql/` | 老师手动 `mysql -u root -p < init.sql` 保底 |

**理由**：三档方案覆盖所有老师机器的可能情况。自动建库建表是首选；环境特殊时用 init.sql 手动导入。

### 2.3 MyBatis-Plus 3.5.7（不是最新版）

**理由**：Spring Boot 3+ 用 jakarta.* 命名空间，4 沿用。3.5.7 是兼容性最稳的版本，更高版本可能在 Spring Boot 4.0.6 上有 SPI 兼容风险。

### 2.4 Spring Security 默认拦截

**现象**：`/doc.html` 访问时弹登录框。
**根因**：`spring-boot-starter-security` 在 classpath 上但没写 SecurityConfig，Spring Security 用默认配置拦截所有请求。
**对策**：A 同学写 SecurityConfig（§七.7.4），放行 `/doc.html`、`/api/auth/**`、`/swagger-ui/**`。

### 2.5 Git 提交策略

**决策**：分多次 commit，第 1 次是基础设施（7 文件），之后是文档和代码。
**理由**：
- 半成品代码（DTO stub）不污染 master 历史
- 每个 commit 单一职责，方便回溯
- 老师翻 `git log` 看得清进度

### 2.6 测试数据的选择

`data.sql` 塞了：
- **1 个 admin 用户**（`admin / admin123`，BCrypt 哈希）—— 登录用
- **1 份示例问卷**（"校园食堂满意度调查"，status=1 已发布）—— 答辩演示用
- **3 道题**（单选/多选/文本各一）—— 覆盖所有题型，演示统计图表

为什么用 BCrypt 哈希？文档 2.4 节明确提供的 `admin123` 对应哈希。不可逆单向加密，数据库泄露也不暴露明文密码。

## 3. 答辩常见 Q&A（8 题）

### Q1：项目里数据库是怎么初始化的？

**答**：3 个 SQL 文件 + 2 个 Spring Boot 配置。

- `schema.sql` 建表
- `data.sql` 插测试数据
- URL 加 `createDatabaseIfNotExist=true` 自动建库
- `continue-on-error=true` 重复启动不报错

老师环境特殊时手动 `mysql -u root -p < sql/init.sql` 兜底。

### Q2：为什么用 MyBatis-Plus？

1. CRUD 不用写 XML，继承 `BaseMapper<T>` 自动获得
2. 条件构造器 `LambdaQueryWrapper` 链式调用
3. 分页插件 `PaginationInnerInterceptor` 一行代码

### Q3：BCrypt 哈希存密码安全吗？

安全。3 个特点：
- **单向**：不可逆
- **加盐**：每次哈希不同
- **慢**：故意设计得慢，暴力破解成本高

`BCryptPasswordEncoder.matches()` 内部重新加盐+哈希后比对。

### Q4：`schema.sql` 和 `data.sql` 的执行顺序？

1. 创建 `DataSource`（Hikari 初始化连接池）
2. 执行 `schema.sql`（建表）
3. 执行 `data.sql`（插测试数据）
4. 启动 Tomcat

**注意**：用 JPA 时 `ddl-auto=update` 会抢先；我们用 MyBatis-Plus 不带 JPA，没冲突。

### Q5：JWT 为什么用 HS256？密钥怎么管理？

- **HS256** = HMAC + SHA-256，对称加密。单体应用够用。
- 生产应该用 **RS256**（非对称），签发和验证用不同密钥。
- 密钥**不应该写死在 properties**，应该用环境变量 / 配置中心。

### Q6：MySQL 的 `utf8mb4` 和 `utf8` 区别？

- MySQL 早期 `utf8` 是 3 字节，**不支持 emoji**
- `utf8mb4` 才是 4 字节真正的 UTF-8
- 2026 年项目**必须用 utf8mb4**

### Q7：SQL 里的 `ON DELETE CASCADE` 是什么？

**答**：级联删除。
- `question.survey_id` CASCADE → 删问卷自动删题目
- `response.survey_id` CASCADE → 删问卷自动删答卷
- `answer.response_id` CASCADE → 删答卷自动删答案
- `answer.question_id` RESTRICT → **不级联**，防止误删题导致历史答卷丢失

### Q8：自动建表方案有什么风险？

- **生产不应该用**：生产应该用 Flyway / Liquibase 做 schema 迁移（有版本控制 + 回滚）
- **不修改已建表**：`CREATE TABLE IF NOT EXISTS` 只在表不存在时执行，改字段类型不会同步
- **我们项目只用于答辩演示**，生产前需要替换
