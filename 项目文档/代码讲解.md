## 三、核心文件讲解（B 重点，老师大概率问）

### 🔵 B 同学写的（你必须会讲）

#### 1. `dto/LoginDto.java`

```java
@Data
public class LoginDto {
    @NotBlank(message = "用户名不能为空")
    private String username;
    @NotBlank(message = "密码不能为空")
    private String password;
}
```

**讲法**："**前端登录时发的数据长什么样**。2 个字段都加 `@NotBlank` 校验，后端会自动拒绝空的用户名密码。`@Data` 是 Lombok 帮我们生成 getter/setter。"

#### 2. `dto/SurveyDto.java`

3 个字段：`id`（编辑时传）+ `title`（必填）+ `description`（选填）。**讲法**："**同一个 DTO 给"创建"和"编辑"两个接口用**。有 id 走 update，没 id 走 insert。"

#### 3. `dto/StatsDto.java`

含**静态内部类** `OptionCount`。**讲法**："**统计接口的返回结构**。每道题一个 StatsDto：选择题有 `options` 列表（选项+票数），文本题有 `texts` 列表（所有回答）。"

#### 4. `service/QuestionService.java`（接口）

4 个方法：`add` / `update` / `delete` / `getBySurveyId`。

**讲法**："**题目的业务接口**。Controller 调它，不知道也不关心具体怎么实现——这是**接口的意义**。"

#### 5. `service/impl/QuestionServiceImpl.java`（实现）

```java
@Service                              // ← 注册成 Spring Bean
public class QuestionServiceImpl implements QuestionService {

    private final QuestionMapper questionMapper;   // ← 构造器注入

    public QuestionServiceImpl(QuestionMapper questionMapper) { ... }

    public Question add(Question q) {
        questionMapper.insert(q);    // ← MyBatis-Plus 自动生成的 insert
        return q;
    }
    ...
}
```

**讲法**："**题目的业务实现**。`@Service` 告诉 Spring 把它放进 IoC 容器。构造器注入 `QuestionMapper`（不用 `@Autowired` 字段注入，是 Spring 4 官方推荐写法）。**自己不写一行 SQL**——`BaseMapper` 已经实现了。"

#### 6. `service/impl/ResponseServiceImpl.java` ⭐ 答辩重点

```java
@Transactional              // ← 关键注解！
public void submit(Long surveyId, Map<Long, String> answers, String ip) {
    Survey survey = surveyMapper.selectById(surveyId);
    if (survey == null) throw new IllegalArgumentException("...");
    if (survey.getStatus() != 1) throw new IllegalArgumentException("...");

    Response response = new Response();
    response.setSurveyId(surveyId);
    responseMapper.insert(response);    // ← 先插 response

    for (Map.Entry<Long, String> entry : answers.entrySet()) {
        Answer answer = new Answer();
        answer.setResponseId(response.getId());
        answerMapper.insert(answer);     // ← 再插多条 answer
    }
}
```

**讲法**："**提交答卷的业务方法**。`@Transactional` 关键——答卷主表 + 答案子表**必须同时成功/失败**，否则数据不一致。提交过程：校验问卷已发布 → 插 response 主记录 → 循环插 answer 子记录。如果中间任何一条失败，**整个方法回滚**，DB 跟没提交过一样。"

**stats() 方法讲法**："**统计方法**。查所有题目 → 查所有答卷 → 查所有答案 → 在 Java 里按 questionId 分组 → 逐题构造统计结果。选择题统计每个选项被选次数，文本题收集所有回答。"

#### 7. `controller/QuestionController.java`

```java
@RestController                                // ← @Controller + @ResponseBody
@RequestMapping("/api/question")               // ← 类级别路径前缀
public class QuestionController {
    @PostMapping                               // ← POST /api/question
    public Result<?> add(@RequestBody Question q) { ... }

    @PutMapping("/{id}")                       // ← PUT /api/question/{id}
    public Result<?> update(@PathVariable Long id, @RequestBody Question q) { ... }

    @DeleteMapping("/{id}")                    // ← DELETE /api/question/{id}
    public Result<?> delete(@PathVariable Long id) { ... }
}
```

**讲法**："**题目的 HTTP 接口**。3 个端点对应 3 个动词——`POST` 新增、`PUT` 修改、`DELETE` 删除。`Result<?>` 是统一返回格式（code + message + data）。"

#### 8. `controller/ResponseController.java`

`POST /api/survey/{id}/submit` ——**匿名提交答卷**。

**讲法**："**提交答卷接口**。`@PathVariable` 取 URL 里的问卷 id，`@RequestBody` 接前端发的答案 JSON。`HttpServletRequest` 拿填写者 IP（防刷会用）。"

#### 9. `controller/StatsController.java`

`GET /api/survey/{id}/stats` ——**统计接口**。

**讲法**："**统计接口**。GET 是 RESTful 的查询动词。返回每道题的选项分布 + 文本回答，**前端拿这个数据画 ECharts 饼图柱状图**。"

### 🔴 A 同学写的（你大概也要会讲）

#### `QqApplication.java`

```java
@SpringBootApplication
@MapperScan("com.example.survey.mapper")
public class QqApplication {
    public static void main(String[] args) {
        SpringApplication.run(QqApplication.class, args);
    }
}
```

**讲法**："**项目启动入口**。`main` 方法跟普通 Java 程序一样。`@SpringBootApplication` 是组合注解（= `@Configuration` + `@EnableAutoConfiguration` + `@ComponentScan`），启动 Spring 容器。`@MapperScan` 让 Spring 扫 mapper 包，把 Mapper 接口注册成 Bean。"

#### `common/Result.java`

```java
@Data
public class Result<T> {
    private int code;       // 200=成功
    private String message;
    private T data;         // 任意类型
    public static <T> Result<T> success(T data) { return new Result<>(200, "操作成功", data); }
    public static <T> Result<T> error(int code, String msg) { ... }
}
```

**讲法**："**所有接口的统一返回格式**。前端只需要判断 `code == 200` 就知道成功，`data` 字段是实际数据。`success()` 和 `error()` 静态方法让 Controller 一行就能返回。"

#### `entity/User.java`（其他 4 个 Entity 类似）

```java
@Data
@TableName("sys_user")              // ← MyBatis-Plus：对应 sys_user 表
public class User {
    @TableId(type = IdType.AUTO)    // ← 主键自增
    private Long id;
    private String username;
    private String password;          // ← 存的是 BCrypt 哈希值
    ...
}
```

**讲法**："**数据库表 sys_user 的 Java 映射**。`@TableName` 标表名，`@TableId` 标主键。`password` 存的是 BCrypt 加密后的值，**不是明文**——登录时 `BCryptPasswordEncoder.matches(明文, 哈希)` 校验。"

#### `mapper/UserMapper.java`（其他 4 个 Mapper 类似）

```java
@Mapper
public interface UserMapper extends BaseMapper<User> {
    @Select("SELECT * FROM sys_user WHERE username = #{username}")
    User selectByUsername(String username);
}
```

**讲法**："**数据库操作接口**。**只要继承 `BaseMapper<T>`，自动获得 insert/select/update/delete 等 17 个方法**——零 SQL。`selectByUsername` 是登录要用的（按用户名查），自己用 `@Select` 注解加的。"

#### `config/SecurityConfig.java`

**讲法**："**Spring Security 配置**。核心 3 件事：放行 `/api/auth/**`（不用登录就能注册登录）、其他请求要 JWT 验证、密码用 BCrypt 加密。"

#### `utils/JwtUtil.java` + `config/JwtAuthFilter.java`

**讲法**："**JWT 工具 + 过滤器**。登录成功 → `JwtUtil.generateToken(userId)` 生成 token → 返回前端 → 前端存 localStorage → 每次请求带 `Authorization: Bearer xxx` 头 → `JwtAuthFilter` 拦截 → 解析 token → 把 userId 放进 Spring SecurityContext → 后续 Controller 通过 `Authentication` 拿到当前用户。"

#### `controller/AuthController.java` + `service/impl/UserServiceImpl.java`

**讲法**："**注册 / 登录端点 + 业务**。`UserServiceImpl.register()` 把密码 BCrypt 加密再存；`login()` 校验密码后生成 JWT 返回。"

## 四、关键概念速查

| 概念 | 一句话讲法 |
|------|-----------|
| **DTO** | API 边界，**只携带数据不做逻辑**——前端发什么字段，DTO 决定 |
| **Entity** | DB 边界，**对应数据库表**——有 `@TableName`、`@TableId` |
| **@Service** | 告诉 Spring 把这个类注册成 Bean |
| **@RestController** | 类注解，说明这是 HTTP 入口，返回 JSON |
| **@RequestMapping** | 路径前缀；`@PostMapping`/`@GetMapping` 等是 HTTP 方法 |
| **@RequestBody** | 把 HTTP 请求的 JSON body 转成 Java 对象 |
| **@PathVariable** | 取 URL 路径里的变量（如 `/api/survey/{id}` 的 id）|
| **@Transactional** | **事务**——方法要么全部成功，要么全部回滚 |
| **@NotBlank** | 字段校验——字符串非 null 非空非纯空格 |
| **JWT** | 无状态 token——登录后服务器签发，前端每次请求带过来 |
| **BCrypt** | 密码哈希——单向加密，不可逆，每次哈希结果不同（带盐）|
| **MyBatis-Plus** | MyBatis 增强——`BaseMapper` 帮你写 CRUD，不用写 SQL |
| **CASCADE** | 数据库外键级联删除——删父表自动删子表 |
| **utf8mb4** | MySQL 真正的 UTF-8（4 字节）——支持 emoji |

## 五、老师可能问的 10 个问题

**Q1**：`QuestionServiceImpl` 跟 `QuestionService` 为什么是 2 个文件？
> 接口定义"能做什么"（合同），实现定义"怎么做"。换实现（比如加缓存、加 Mock）不影响 Controller。

**Q2**：`@Transactional` 起什么作用？为什么答卷提交要用？
> 事务控制。**答卷主表 + 答案子表必须同时成功/失败**——不能答卷插进去了但答案没插上（数据不一致）。`@Transactional` 保证方法执行时任何一个 SQL 失败，整个方法回滚。

**Q3**：你们的密码怎么存的？
> **BCrypt 哈希**，单向加密，不可逆。数据库里存的是类似 `$2a$10$N9qo8uLOi...` 的字符串，不是明文。登录时 `BCryptPasswordEncoder.matches(明文, 哈希)` 校验。

**Q4**：JWT 是什么？跟 Session 比呢？
> JWT 是无状态的 token，**服务器不存**——所有用户信息都编码在 token 里。优点：跨域友好、适合前后端分离、不用 session 共享。缺点：token 一旦签发就不能主动失效（要靠过期时间）。

**Q5**：DTO 跟 Entity 区别？为什么不直接用 Entity？
> **DTO 是 API 边界**（前端发的数据），**Entity 是 DB 边界**（数据库表）。比如 User Entity 有 `password` 字段（哈希值），绝不能通过 API 暴露给前端——用 DTO 就把它过滤掉了。**Entity 字段 ≥ DTO 字段**是普遍规则。

**Q6**：MyBatis-Plus 怎么用？跟 MyBatis 区别？
> **MyBatis-Plus 在 MyBatis 之上**，主要加了两个能力：① 继承 `BaseMapper<T>` 自动获得 17 个 CRUD 方法，不用写 XML；② 提供 `LambdaQueryWrapper` 链式 API，**类型安全**的条件查询（`Question::getSurveyId` 而不是字符串 `"survey_id"`）。

**Q7**：5 张表怎么设计的？有哪些外键？
> ER 关系：`sys_user 1:N survey 1:N question`；`survey 1:N response 1:N answer`；`answer N:1 question`。
> 外键策略：用户→问卷 RESTRICT（删用户不删他的问卷），问卷→题目/答卷 CASCADE（删问卷级联删），答案→题目 RESTRICT（防误删题导致历史答卷丢失）。

**Q8**：统计 SQL 怎么写？量大怎么办？
> 现在数据小，**在 Java 里用 stream 分组**（`Collectors.groupingBy(Answer::getQuestionId)`）。数据量大（>10 万条）应该改用 SQL `GROUP BY` 加聚合，**少一次 DB→Java 的数据传输**。

**Q9**：`schema.sql` 跟 `data.sql` 谁先执行？
> Spring Boot 启动时：先建 `DataSource` 连接池 → 执行 `schema.sql` 建表 → 执行 `data.sql` 插测试数据 → 启动 Tomcat。`continue-on-error=true` 让第二次启动不报错（已存在的表/重复插入都跳过）。

**Q10**：项目最难的部分是什么？
> 答卷提交的**事务控制**——主表 + 子表要原子性提交。还有**统计的多题型适配**——单选/多选要拆分逗号、文本题直接收集，对每个题型分别处理。
